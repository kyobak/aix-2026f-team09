## 1. 활동 목적

**박재원**: 그럼 2주차 활동 시작할게요. 이번 주 목표는 코딩 에이전트한테 주는 컨텍스트가 달라지면 결과물이 어떻게 달라지는지 직접 확인해 보는 거예요.

**박지성**: 주제는 메모 검색 기능이죠? 같은 기능을 조건만 다르게 해서 만들어 보고 비교하는 걸로 알고 있어요.

**박재원**: 맞아요. 메모 검색 기능을 각자 구현해 보고, 결과를 나란히 놓고 비교해 보려고 합니다.

## 2. 활동 내용

**강태혁**: 조는 어떻게 나눌까요?

**박재원**: A조는 태혁 님이랑 시준 님, B조는 저랑 지성 님으로 가죠.

**전시준**: 그럼 A조는 어떤 조건으로 하면 돼요?

**박재원**: A조는 "메모 검색 기능을 만들어줘"라는 한 줄 지시만 주는 거예요. 추가 정보는 없이요.

**박지성**: B조는 CONVENTIONS.md, schema.sql, service.js, routes.js 같은 프로젝트 정보를 같이 주고, 구체적인 종료조건까지 명시해서 요청하기로 했어요.

**강태혁**: 기능은 같은데 주는 정보량만 다르게 하는 거네요. 알겠습니다.

## 3. 결과 및 비교

**박재원**: 다들 구현 끝났으면 결과 공유해 볼까요? A조부터 부탁드려요.

**강태혁**: 검색 기능 자체는 돌아가긴 했어요. 그런데 기존 프로젝트 구조나 규약은 거의 반영이 안 됐더라고요.

**전시준**: 응답 형식이 기존 API랑 다르게 나왔고, 입력 검증도 빠져 있었어요. 계층 분리도 안 돼 있어서 로직이 한쪽에 몰려 있었고요.

**강태혁**: 제일 심각했던 건 사용자 권한 처리예요. 다른 사용자의 메모까지 검색 결과에 나오는 걸 확인했어요.

**박지성**: 그건 실제 서비스였으면 바로 문제가 됐겠네요.

**박재원**: 그러게요. B조 결과도 공유할게요. 지성 님이 먼저 설명해 주실래요?

**박지성**: B조는 기존 코드랑 프로젝트 규약을 참고해서 `GET /memos/search?q=키워드` 형태로 구현했어요. 제목과 본문을 기준으로 검색하고, `user_id` 조건을 걸어서 본인 메모만 반환되도록 했습니다.

**박재원**: 거기에 제가 LIKE 패턴에 ESCAPE 처리를 추가해서 보완했어요. 검색어에 `%`나 `_` 같은 특수문자가 들어와도 의도대로 검색되게 하려고요.

**전시준**: A조에서 문제가 됐던 부분들이 B조에서는 대부분 해결돼 있네요.

## 4. 논의 및 느낀 점

**박재원**: 두 결과를 비교해 보니까 어떤 생각이 드세요?

**강태혁**: 저는 에이전트한테 정확한 컨텍스트를 주는 게 정말 중요하다는 걸 느꼈어요. 한 줄 지시만으로는 기존 프로젝트의 구조나 규칙을 파악하기가 어려운 것 같아요.

**전시준**: 동의해요. 기능이 "돌아가는 것"과 "기존 코드에 맞게 만들어지는 것"은 완전히 다른 문제더라고요.

**박지성**: B조에서 써 보니까 관련 파일이랑 규약, 종료조건을 같이 주면 기존 코드에 맞는 결과가 나올 가능성이 확실히 높아졌어요.

**박재원**: 특히 CONVENTIONS.md가 응답 형식, 계층 분리, 권한 처리 같은 기준을 잡아 준 게 컸던 것 같아요.

**박지성**: 기존 routes.js랑 service.js도 도움이 많이 됐어요. 실제 프로젝트 구조가 어떤지, 코드를 어떤 방식으로 쓰는지 에이전트가 이해하는 데 참고가 됐으니까요.
