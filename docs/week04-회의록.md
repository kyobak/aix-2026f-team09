4주차 회의록

작성일: 2026-09-23
참여자: 박재원, 박지성, 강태혁, 전시준
회의 주제: 주제 선택과 요구사항 명세 / 문제 선택 및 사양 작성

1. 회의 목적

이번 주에는 3주차에 조사한 학교생활의 여러 문제를 바탕으로 프로젝트에서 해결할 문제를 구체적으로 선정하고, 선정한 문제의 요구사항과 승인 기준을 작성하였다.

팀원들은 학생들이 일상적으로 겪는 대기와 관련된 불편함을 중심으로 논의하였으며, 학생식당·푸드코트의 대기시간 안내와 세탁실의 사용 상태 및 대기열 안내 등을 구체적인 문제로 다루었다.



2. 성공 기준 구체화

3주차에 작성했던 성공 기준에는 '쉽게 확인한다', '혼잡도', '줄이 길다', '가기 전에'와 같이 구체적인 판단 기준이 없는 표현이 있었다.

이번 회의에서는 이러한 표현을 실제 시스템에서 측정하고 테스트할 수 있도록 다음과 같이 구체화하였다.

혼잡도 → 대기 구역 인원(명)과 예상 대기시간(분)
쉽게 확인 → 앱 첫 화면에서 1회 탭 이내에 해당 장소의 수치를 확인
줄이 길면 → 예상 대기시간이 10분 이상인 경우
가기 전에 → 현재로부터 60초 이내에 측정된 값을 사용

이를 통해 기존의 모호한 성공 기준을 실제 구현과 테스트에 사용할 수 있는 수치와 조건으로 변경하였다.

3. 승인 기준 작성

구체적인 요구사항을 검증하기 위해 EARS 형식으로 승인 기준을 작성하였다.

학생식당 관련 기준

대기 인원과 분당 처리 인원을 측정하여 예상 대기시간을 계산한다.
계산된 예상 대기시간을 10초 이내에 이용자 화면에 표시한다.
실제 대기 인원과 배식 처리량을 측정하여 앱에 표시되는 값과 비교한다.

세탁기 관련 기준

세탁기 진동이 30초 이상 계속되면 해당 기기를 '사용 중'으로 표시한다.
대기자가 있는 세탁기가 비면 대기열 1순위 이용자에게 5초 이내에 알림을 보낸다.
호출된 이용자가 5분 이내에 기기를 사용하지 않으면 해당 호출을 취소하고 다음 순번 이용자에게 알림을 보낸다.

공통 및 예외 상황

카메라가 영상이나 이미지를 서버로 보내려고 하는 경우 해당 데이터를 받지 않고 영상·이미지를 저장하지 않는다.
같은 이용자가 같은 장소의 혼잡도를 10분 이내에 다시 제보하는 경우 중복 제보를 제한하고 다음 제보가 가능한 시간을 안내한다.

5. 테스트 방법
각 승인 기준이 실제로 충족되는지 확인할 수 있도록 테스트 방법도 함께 작성하였다.

학생식당은 점심시간에 실제 대기 인원을 세고 1분 동안 배식구를 통과하는 인원을 측정한 뒤 예상 대기시간을 직접 계산하여 앱에 표시되는 값과 비교하기로 하였다.
또한 대기열이 눈에 띄게 증가하거나 감소했을 때 화면의 정보가 10초 이내에 갱신되는지도 확인한다.

세탁기는 실제 기기에 센서를 부착하여 작동 상태를 측정하고, 정해진 시간이 지난 후 앱의 상태가 '사용 중'으로 변경되는지 확인한다.
대기자가 있는 경우에는 기기가 비었을 때 첫 번째 순번의 휴대폰으로 알림이 5초 이내에 전달되는지 확인한다. 호출 후 사용하지 않는 상황에서는 5분 뒤 다음 순번으로 넘어가는지도 테스트한다.

카메라와 관련된 기능은 서버에 이미지나 영상이 저장되지 않는지 확인하고, 필요한 숫자 수준의 데이터만 전송되는지 점검한다.

6. 회의 결과

이번 회의를 통해 학생식당·푸드코트의 예상 대기시간 안내와 세탁실의 사용 상태 및 대기열 안내를 주요 문제로 구체화하였다.

또한 기존의 모호한 성공 기준을 수치와 시간 조건을 포함한 구체적인 요구사항으로 변경하고, 정상적인 상황뿐만 아니라 중복 제보나 불필요한 이미지·영상 저장과 같은 예외 상황까지 고려하여 승인 기준을 작성하였다.

각 요구사항에 대한 실제 테스트 방법도 함께 정리하여 이후 개발 과정에서 기능이 제대로 구현되었는지 확인할 수 있도록 하였다.
