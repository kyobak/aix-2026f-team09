## 1. 활동 목적 및 주제 확정

**박재원**: 그럼 5주차 활동 시작하겠습니다. 이번 주는 프로젝트 주제를 확정하고, 필요한 작업과 담당, 작업 순서를 정리하는 시간이에요. 이번 학기에 구현할 범위와 가장 먼저 동작시킬 흐름도 정해야 합니다.

**박지성**: 주제는 ERICA 캠퍼스 대기 현황 웹앱으로 정리하면 되겠죠? 학식 식당, 세탁실, 오픈스페이스, 셔틀콕에 가기 전에 현재 상황을 휴대폰으로 확인하는 서비스예요.

**전시준**: 장소마다 필요한 정보는 조금 다를 것 같아요. 학식은 예상 대기시간, 세탁실은 기기 사용 여부, 오픈스페이스는 혼잡도, 셔틀콕은 대략 몇 번째 버스를 탈 수 있는지가 필요하겠네요.

**강태혁**: 공통된 목적은 직접 갔다가 이용하지 못하고 돌아오는 헛걸음을 줄이는 거고요. 장소의 현재 상황을 먼저 확인할 수 있게 하는 방향으로 잡으면 되겠습니다.

**박재원**: 3주차에 정리한 문제 정의에서도 학식과 셔틀콕의 대기줄, 세탁실과 오픈스페이스의 이용 가능 여부를 미리 알기 어렵다는 점을 다뤘죠. 그 내용을 바탕으로 이번 주에는 이 주제로 확정하겠습니다.

**박지성**: 다만 모든 장소를 처음부터 동시에 구현하면 범위가 넓어지니까, 먼저 간단한 흐름부터 동작시키는 게 좋겠어요.

**전시준**: 우선 학식 화면에서 예상 대기시간이 나오는 것부터 시작하고, 이후 다른 장소의 정보를 연결하면 되겠네요.

## 2. 태스크 분해와 담당 결정

**박재원**: 작업은 각각 완료 여부를 확인할 수 있도록 나누겠습니다. 담당도 ‘다 같이’가 아니라 한 명씩 정해두고요.

**박지성**: 저는 먼저 학식 줄을 관찰하겠습니다. 점심시간에 줄 인원과 배식 속도를 직접 세어서 기록할게요. 계산에 사용할 실제 값을 확보하는 작업입니다.

**전시준**: 저는 장소별 화면 구성을 맡겠습니다. 화면 스케치를 만들고 팀원들이 확인해서 합의하면 완료한 것으로 하죠.

**박재원**: 대기시간 계산은 제가 맡을게요. 줄 인원과 처리 속도를 입력했을 때 손으로 계산한 값과 같은 결과가 나오는지 확인하겠습니다.

**강태혁**: 저는 카메라로 인원을 세는 기능을 맡겠습니다. 카메라가 센 인원과 사람이 직접 센 인원을 비교하고, 영상은 저장하지 않는 방식으로 구현할게요.

**박지성**: 그러면 제가 학식 줄 관찰을 먼저 하고, 그 자료를 태혁 님이 인원 계산 결과를 확인할 때 활용하면 되겠네요.

**전시준**: 화면 구성과 대기시간 계산이 준비되면 제가 학식 화면에 예상 대기시간을 표시하겠습니다. 휴대폰에서 학식 화면을 열었을 때 값이 보이면 완료로 확인할 수 있어요.

**박재원**: 이후 실시간 UI는 제가 맡겠습니다. 송신용 휴대폰에서 보낸 값이 들어오면 새로고침하지 않아도 화면이 바뀌도록 하겠습니다.

**강태혁**: 세탁기는 진동으로 상태를 구분하는 방식이죠? 돌아갈 때와 멈췄을 때의 차이를 먼저 확인해야 할 것 같아요.

**박지성**: 세탁기 진동 관찰도 제가 맡겠습니다. 작동 중일 때와 멈췄을 때의 차이를 확인해서 기록할게요.

**강태혁**: 그 기록과 실시간 UI를 바탕으로 제가 세탁실 화면에 ‘사용 중’과 ‘비어 있음’을 표시하겠습니다.

**박재원**: 세탁기 상태 표시가 준비되면 제가 줄서기와 알림 기능을 연결할게요. 앱에서 줄을 서 둔 뒤 세탁기가 비었을 때 내 차례 알림이 오는 흐름입니다.

**박지성**: 오픈스페이스와 셔틀콕 관찰도 제가 맡겠습니다. 오픈스페이스의 좌석 수와 실제 인원, 셔틀콕의 줄 인원과 버스 한 대에 타는 인원을 기록할게요. ‘여유’와 ‘혼잡’을 구분할 기준은 그 자료를 보고 팀에서 정하겠습니다.

**강태혁**: 오픈스페이스 혼잡도 표시는 제가 맡겠습니다. 카메라로 센 인원을 바탕으로 화면에 ‘여유’ 또는 ‘혼잡’이 나오게 할게요.

**전시준**: 셔틀콕 탑승 안내는 제가 맡겠습니다. 줄 인원과 버스 정원을 이용해서 대략 몇 번째 버스를 탈 수 있는지 표시하겠습니다.

**박지성**: 마지막 시연 점검은 제가 맡겠습니다. 각 장소 화면에 표시되는 값을 현장에서 직접 확인한 값과 비교하겠습니다.

## 3. 의존 관계와 작업 순서 확인

**박재원**: 이제 어떤 작업이 먼저 끝나야 하는지 확인하겠습니다. 바로 시작할 수 있는 건 학식 줄 관찰, 화면 구성, 대기시간 계산, 세탁기 진동 관찰, 오픈스페이스와 셔틀콕 관찰이에요.

**전시준**: 학식 대기시간 표시는 화면 구성과 계산 기능이 모두 준비돼야 할 수 있겠네요.

**강태혁**: 카메라 인원 세기는 학식 줄 관찰 자료가 먼저 필요하고요. 실시간 UI는 학식 화면과 카메라 인원 세기 기능이 준비된 다음에 연결하는 것으로 정리돼 있습니다.

**박재원**: 세탁기 사용 여부 표시는 실시간 UI와 진동 관찰 결과가 필요합니다. 그다음에 줄서기와 알림을 구현하고요.

**박지성**: 오픈스페이스 혼잡도와 셔틀콕 탑승 안내는 실시간 UI, 그리고 두 장소의 관찰 결과가 준비되면 진행할 수 있겠네요.

**전시준**: 마지막 점검은 세탁기 줄서기와 알림, 오픈스페이스 혼잡도, 셔틀콕 탑승 안내가 끝난 뒤에 하는 것으로 하겠습니다.

**강태혁**: 의존 관계를 확인했을 때 서로의 완료를 기다리는 사이클은 없네요.

**박재원**: 활동지의 작업 순서는 1번부터 13번까지로 정리하겠습니다. 다만 선행 작업이 없는 관찰 작업들은 앞의 작업이 모두 끝날 때까지 기다릴 필요 없이 각 담당자가 진행할 수 있어요.

**박지성**: 그러면 관찰과 화면 구성, 계산 기능은 함께 시작하고, 결과가 필요한 작업은 선행 작업이 끝나면 이어서 진행하겠습니다.

## 4. 구현 범위와 실행 가능성 논의

**박재원**: 필수 범위는 학생이 공용시설의 현재 상황을 바탕으로 계산한 예상 대기시간을 실시간 화면에서 확인하는 흐름입니다.

**전시준**: 먼저 학식 대기시간을 확인하는 흐름을 동작시키고, 세탁실·오픈스페이스·셔틀콕 기능을 추가하는 순서로 진행하면 되겠어요.

**강태혁**: 세탁실은 빈 세탁기 확인과 줄서기 알림, 오픈스페이스는 혼잡도 확인, 셔틀콕은 예상 탑승 순서 확인을 Should 범위로 두겠습니다.

**박지성**: 사용자 제보로 혼잡도를 보완하는 기능은 Could로 정리하죠. 직접 계산한 값과 이용자가 느끼는 상황이 다를 때 보완할 수 있겠지만, 기본 기능을 먼저 구현해야 하니까요.

**박재원**: 이번 학기에 하지 않을 항목도 확인하겠습니다. 학교 CCTV 연동은 허가와 개인정보 문제로 진행하기 어려워서 제외합니다.

**강태혁**: 대신 송신용 휴대폰 카메라나 직접 촬영한 영상을 활용하고, 앱에서는 영상을 저장하지 않고 인원 숫자만 사용하겠습니다.

**전시준**: 학번 로그인과 실제 세탁기 예약도 제외하는 거죠?

**박재원**: 네. 학번이나 이름은 받지 않을 계획이고, 앱을 사용하지 않는 학생의 현장 이용까지 통제할 수 없어서 실제 예약을 보장하기 어렵습니다. 앱 안의 줄서기와 알림을 구현하더라도 실제 세탁기 이용권을 확보하는 예약과는 구분해야 해요.

**박지성**: 세탁기 진동을 측정하려면 센서가 필요한데, 준비가 어려울 수도 있겠습니다.

**강태혁**: 저렴한 진동 센서를 준비하는 방향으로 하되, 어려우면 가짜 데이터로 상태 변화를 대신 보여주겠습니다.

**박재원**: 유료 API는 사용하지 않고, 학번이나 이름 같은 개인정보도 받지 않는 것으로 정리하겠습니다.

**전시준**: 15주차 발표에서는 송신용 휴대폰과 시청용 휴대폰 또는 노트북으로 시연할 수 있겠네요. 송신 화면에서 현장이나 장소별 영상을 비추면 시청 화면의 값이 바뀌는 모습을 보여주는 방식이에요.

**강태혁**: 세탁기는 가짜 데이터로 사용 중과 비어 있음 상태를 바꾸면서 줄서기와 알림 흐름을 보여주면 되겠습니다.

**박지성**: 실제 관찰값과 가짜 데이터로 보여주는 부분은 발표할 때 구분해서 설명해야겠어요.

## 5. 첫 동작 흐름과 마무리

**박재원**: 가장 먼저 동작시킬 흐름은 카메라나 센서까지 붙이지 않고, 직접 입력한 값으로 시작하겠습니다.

**전시준**: 학식 줄 인원과 처리 속도를 입력하면, 인원을 처리 속도로 나눠 예상 대기시간을 계산하고, 휴대폰 학식 화면에 ‘약 몇 분’이 뜨는 흐름이죠.

**강태혁**: 우선 입력부터 계산, 화면 표시까지 연결되는지 확인한 다음에 카메라로 센 인원을 입력값으로 바꾸면 되겠네요.

**박지성**: 저는 학식 관찰부터 시작하고, 세탁기와 다른 장소의 관찰 자료도 준비하겠습니다.

**전시준**: 저는 화면 스케치를 먼저 만들고, 계산 기능이 준비되면 학식 화면에 연결하겠습니다. 이후 셔틀콕 안내 화면을 맡겠습니다.

**박재원**: 저는 대기시간 계산부터 구현하고, 이후 실시간 UI와 세탁기 줄서기·알림을 진행하겠습니다.

**강태혁**: 저는 카메라 인원 세기와 세탁기 상태 표시, 오픈스페이스 혼잡도 표시를 맡겠습니다. 인원 비교와 영상 저장 여부도 확인할게요.

**박재원**: 오늘 정한 태스크, 담당, 의존 관계와 구현 범위를 활동지에 반영하겠습니다. 수업 종료 시 `docs/week-05.md`를 저장하고, ‘docs: 5주차 활동지 작성’이라는 메시지로 커밋하는 것으로 마무리하겠습니다.
